# Android 定位模拟工具：项目规范文档

> 日期：2026-11-10。本文记录首版开发、验证和发布约定。

## 1. 基本原则

- 首版聚焦 Android，不为尚未开展的 iOS 提前增加跨平台框架或抽象层。
- 实现与需求直接相关的最小方案；先满足清晰的验收目标，再扩展功能。
- 本地优先；不自行收集真实位置、坐标轨迹和密钥，不在日志中输出敏感位置。
- Android 模拟位置会被系统标记，不提供隐藏、规避标记或保证其他应用接收的承诺。
- 需求、架构、代码行为变更时同步修改对应文档，明确未实现和已实现的区别。

## 2. 环境与构建

使用 Android Studio、Android SDK、Gradle Wrapper 和 JDK 21。Gradle 守护进程和编译工具链使用 JDK 21，Java 与 Kotlin 的字节码目标均为 17。依赖在 Gradle 版本目录中固定。

常用命令如下：

```powershell
.\gradlew.bat assembleDebug
.\gradlew.bat testDebugUnitTest
.\gradlew.bat lintDebug
.\gradlew.bat assembleRelease
```

`assembleRelease` 能否生成可安装包取决于签名配置。测试分发可以使用 Debug APK；长期使用和分发使用签名 Release APK。密钥库、密码、地图密钥等不提交仓库，使用本地安全配置或构建环境注入；不要在文档、截图或日志中展示。应妥善备份签名密钥；升级安装需签名兼容。Google Play 签名和直接 APK 分发方式如同时使用，发布前应核实签名策略。

## 3. 建议目录

```text
app/src/main/
  java/<application-id>/
    ui/            界面、ViewModel 和状态
    map/           地图展示与坐标系适配
    simulation/    参数校验、漂移算法与会话模型
    platform/      前台服务、通知与系统模拟位置适配
    data/          本地配置与选点历史读写
  res/             字符串、图标、主题等资源
app/src/test/      不依赖设备的单元测试
app/src/androidTest/  需要 Android 环境的集成测试
docs/              产品、设计与项目规范
```

目录仅用于表达职责，不要求提前创建空包或空接口。跨包调用只传需要的数据；不得通过 UI 持有长生命周期的 Activity 或 View 引用。

## 4. Kotlin 和 UI 约定

| 对象 | 命名 | 示例 |
| --- | --- | --- |
| 类型、Compose 组件 | 大驼峰 | `SimulationConfig`、`MapScreen` |
| 函数、属性 | 小驼峰 | `startSimulation`、`radiusMeters` |
| 常量 | 全大写下划线 | `DEFAULT_INTERVAL_SECONDS` |
| 资源 | 小写下划线 | `simulation_start` |
| 单位 | 名称明确单位 | `radiusMeters`、`intervalSeconds` |

采用 Kotlin 官方编码习惯；优先不可变数据和值对象。公开界面文案放到字符串资源，颜色、排版和形状集中管理；避免为单个页面引入额外 UI 库。Compose 页面按状态渲染，把用户操作交给 ViewModel；避免在组件重组中直接启动服务或发起位置注入。

```kotlin
// 示例：逻辑接收明确单位，不依赖界面。
fun isValidRadius(radiusMeters: Int): Boolean = radiusMeters in 1..5_000
```

反例：在 `@Composable` 函数体中每次重组都调用启动服务，会造成重复启动且难以测试。启动应由用户事件触发，状态由服务和 ViewModel 同步。

## 5. 系统能力和数据规范

- 在地图 SDK 边界显式标注坐标系；内部及系统注入统一 WGS-84，不能将地图显示坐标直接当作系统坐标使用。
- 所有距离以米、时间以秒表示；边界计算和纬经度合法性在模拟层校验，不能仅依赖 UI 输入限制。
- 测试位置注册、注入、移除放在系统适配层；处理授权撤销和异常，不隐藏模拟标记。
- 前台服务只由用户明确发起；通知展示运行状态和停止入口。系统版本所需的服务类型和权限必须按实际实现验证，不默认申请后台定位。
- 所有结束路径尽力清理提供器；崩溃、强制停止或权限撤销不保证清理成功，不能误报定位已恢复。
- 当前配置、选点历史、置顶、收藏及外观设置保存在本机。历史仅记录用户确认的中心点，运行时漂移输出留在内存。地图服务可能产生网络请求，实际接入前确认其使用条款与隐私披露。

## 6. 测试与验收

- 单元测试放 `src/test`，以功能命名；至少覆盖参数上下限、固定坐标、漂移圆内与步长约束、地理边界、失败状态。
- 在可控随机源下测试漂移；不能只断言函数被调用，要断言真实地理距离和输出结果。
- Android 集成测试和手工真机覆盖首次授权、首次注入、停止、权限撤销、通知、进程中断、锁屏及目标应用接收情况。
- 每次修复优先构造能复现的问题或明确复现步骤；根据改动运行对应单元测试、lint、构建和必要真机验证，记录未验证范围。
- 必须使用 Release 包测量实际体积；记录构建类型、ABI 和是否包含地图 SDK，避免把安装体积与 APK 下载体积混为一谈。

## 7. 依赖与版本管理

- `versionName` 使用 `主版本.次版本.修订号`。不兼容变更升主版本，新增功能升次版本，修复或可交付的小调整升修订号。升级高位时将低位归零。
- 每次交付不同内容的安装包，都在 `app/build.gradle.kts` 更新 `versionName` 并递增整数 `versionCode`。同一版的不同手机架构使用同一版本号。
- 对外交付使用 `dist/vX.Y.Z/LocationLab-vX.Y.Z-渠道-架构.apk`。`debug` 用于开发调试，`preview` 用于测试分发，`release` 用于正式分发并使用正式签名。例如 `dist/v0.2.0/LocationLab-v0.2.0-preview-arm64-v8a.apk`。使用 `scripts/Export-Apk.ps1` 归档，保留已交付文件，避免用不同内容覆盖同名版本。

- 地图 SDK 上线前检查覆盖地区、坐标系、隐私、商用许可、价格、最低系统版本和包体。
- 首版默认 Compose Material 3；外观可以自定义，第三方组件库只有在明确解决需求、维护状况和许可证通过检查后引入。
- 不为一两个页面预先搭建大型架构、数据库、依赖注入框架或复杂路由；确有需求时再评估。
- 第三方依赖升级需记录影响，并重新运行与改动相关的构建、测试及地图/模拟真机验证。

## 8. 提交和评审建议

- 一次改动聚焦单一目的；提交前检查差异，避免加入生成产物、密钥和无关格式修改。
- 建议使用 `feat:`、`fix:`、`docs:`、`test:` 等前缀，简短说明意图；如团队之后已有约定，以团队约定为准。
- 评审重点：需求是否可验收、坐标系和单位是否正确、授权与清理是否可靠、后台限制是否明确、隐私与包体影响是否可解释。
- 发布前检查安装、同签名更新、模拟位置选择引导、前台通知、停止与异常中断、坐标范围和真机兼容结果。
